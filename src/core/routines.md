## Routines

A **routine** mirrors a scheduled trigger that lives at its source — a harness's scheduler, cron, a cloud routine — so the board knows which recurring tasks start on their own, where and how. One file per routine, `<scope>/.flows/routines/<name>.md`, written through `TASKS routine …`: `name`, `accessors` (contributors who can reach the trigger's source), `mode` (`attended`: exactly one task, and the user is reached when it needs them; `unattended`: its tasks run in one session and share its context), `environment` (the registered environment it runs in), `schedule` (what the trigger is set to: a cron expression and an IANA zone in the recurring syntax, or one fire time as a timestamp with offset), `trigger` (one line: what it is and where, with its identifier), `status` (`active`/`paused`), `formerly`, `created`; body = how to change or remove the trigger at its source. Former names stay reserved and keep resolving, as for agents and environments; `rm` is refused while a task points at the routine, and `env rm` while a routine runs there. `paused` is the board-side off switch for anyone who cannot reach the source: the trigger still fires, and the wake stops on it. Setting one up for a task, or moving a task to another, is `/{{skill}} schedule <id> [<routine>]` (`shared/routes/schedule.md`).

A recurring task points at a routine with its `routine` field (`add` / `update --routine <name>`, `""` clears). A routine's tasks share one type, so `/dev` and `/ops` each wake only their own; a second task on an attended routine is refused; pointing a task at an unattended routine notes the shared session, and warns when the task's flow has `[user]` steps nobody will be there to do. Changing its kind away from `recurring` is refused while the routine is set — clear the routine first. Editing a covered task's cadence, schedule or `next_due` prints a reminder that its trigger lives at the source and may need the same change there.

**Not started.** A covered task that is due, at rest (`backlog`/`planned`) and has no open `needs`, whose routine's schedule says it should have fired for it more than an hour ago, reads `🚨routine <name> did not start` on its line, and its index id carries `🚨` in place of `⏰` — `routine <name> paused` (plain `⏰` on the id) when the routine is paused. It is derived whenever the board is read, never stored; `TASKS routine list` shows the same under each routine with the time it should have fired. A schedule this machine cannot read (say, a zone its timezone data lacks) is listed as `schedule unreadable (<why>)` and skipped by the check rather than stopping the board.

**Wake.** `TASKS routine wake <name>` is the gate a routine's run passes first: exit 2 with the reason when the routine is paused, no longer on the board, or runs the other skill's tasks; otherwise its due tasks at rest (`backlog`/`planned`), in due order — a scheduled task counts as due once inside its time's early window (see *Recurring*), so an early fire still runs it — then any due one with an open `needs` on a `skipped, waiting on a decision:` line and any still in flight on a `skipped, in flight:` line — a re-fire never hands out a parked question again, nor a run that is still going. A trigger's prompt is only `/{{skill}} wake <name> <dir>`, `<dir>` being the product directory's absolute path in its environment (`shared/routes/wake.md`): every rule a scheduled run follows lives in the skill and on the board, so the prompt at the source changes only if the checkout moves.

**Runner environment.** The environment a routine runs in must give a session everything a run needs with no one at the keyboard: a checkout of this repo that can push to the integration branch, with the product directory at the path the trigger's prompt names; this skill at a version the board accepts; `gh` signed in as a login on the board's roster (`TASKS whoami` checks it at the wake); for dev tasks, the right to open PRs; every tool call the run makes either allowed or refused up front, never left waiting on a permission prompt; and, for an attended routine, a way to notify the user. These are judged when the routine is set up and by watching its first run — the script does not check them.
