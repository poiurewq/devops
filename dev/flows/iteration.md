# /dev iteration — show / close / new

An iteration = one integration branch + its board. Task ids reset each iteration; the iteration itself is a positive integer. Cross-iteration references are `<n>/T<id>` (log.md lines are already written that way). A board with no `parent_branch` (typically integration is `main`) closes in place: archive, then start the next iteration on the same branch — no parent merge, no new integration branch. Branched iterations still land into the parent, then start on a new branch.

**Identity is the integer.** `board.yml` `iteration` is `1`, `2`, `3`… (default 1 at init; `init --iteration N` to match a team already in progress). `iteration_name` is an optional display label. Archive dirs are `{n}-{slug}` (or `{n}` if unnamed); clash is on the number, not the slug. `iteration_started` is `YYYY-MM-DD`, stamped at init / iteration-new (today unless given) and settable so it can match an external calendar. Close writes `started:` / `closed:` lines under `## {n}` (or `## {n} — {name}`). Ship titles PRs `[n/T<id>] …` (`[<scope> n/T<id>] …` on a scoped board).

## `/dev iteration` — show

`TASKS iteration`: scope, index, display name, start date, branch, parent, done/in-play (later and shelved omitted from the denominator).

`TASKS config iteration <n>` renumbers the live iteration (refused if that number already has an archive). `config iteration_name` / `config iteration_started` adjust the label and start date. All three are refused once the iteration is closed but not yet landed or rolled in place, since the close heading in log.md is `## {n}`.

## `/dev iteration close`

1. Confirm intent. If unfinished tasks exist, ask per task: finish it, **park later** (`--status later` — not this iteration; reseeds still-later until someone picks it; does not block close), **shelve** it (`--status shelved --reason "<why>"` — not needed for now; comes back still shelved, holds no area), **carry over** (moves into the next iteration with status, assignee, branch and PR intact, in-flight drafts included; only its id changes), or **drop** it (`--status not-planned --reason "<why>"`, or delete — user's choice). Dropped, later and shelved tasks don't block the close and need no `--force`. Umbrella tasks deserve scrutiny here: an unfinished umbrella means the iteration's goal isn't actually met, so closing anyway should be a deliberate call, not a shrug. One whose children all look done is not finished either — it needs its verification pass (`/dev <id>`, SKILL.md *Umbrella close*); never close one with `--status done`.
2. `TASKS iteration-close`. When the user chose to carry the leftover unfinished tasks, add `--carry`: carry is all-or-nothing, so finish, park, or drop the ones that should not come along first. `--force` instead logs the leftovers as unfinished and leaves them behind (their branches and PRs orphaned) — only after the user accepts that list; genuinely abandoned tasks should be `not-planned` first, parked work `later`, and work not needed for now `shelved`. This copies every task file verbatim to `.tasks/archive/<n>-<slug>/NNN.md` — the full record, greppable and browsable long after the iteration — and indexes them in `.tasks/log.md` (one line per task with area, PR, and `[not planned]` / `[later]` / `[shelved]` / `[carried: …]` / `[unfinished: …]` flags, each task's `Shipped (<date>): …` records under it), then removes the live files. Nothing is lost; point people at the archive, not at git history of a deleted file.
3. **No parent — roll in place.** Ask the user for the next iteration's display name, then `TASKS iteration-new --name <name>` (omit the branch; `--iteration N` / `--iteration-started D` as needed). A name is optional (unnamed iterations are fine); still ask. Skip land. The script refuses unless step 2 has run (empty board + log.md close section).
4. **Has parent — land the iteration**: `TASKS iteration-land` (opens the PR if needed, then merges with a **merge commit**, not squash). Requires a closed board: no live task files and a `log.md` close section for the current iteration (what step 2 writes). Use `--create-only` when review should happen first via flows/review.md; the integrator typically owns the merge. Do not hand-roll `gh pr create` / `gh pr merge --merge` here — that includes when the agent harness refuses `iteration-land`: that is not a script error, so surface it, say the land never ran, and stop (flows/init.md step 5). Task-level history should survive in the parent. Then `/dev iteration new <branch>` below.

## `/dev iteration new [<branch>]`

**In place (no parent):** after close, `TASKS iteration-new [--name n] [--iteration N] [--iteration-started D]`. Stays on the current integration branch; no pointer commit. Passing a different branch without `--parent` is refused; `--parent` plus a new branch is the branched path below. Carried, later and recurring tasks reseed the same way as on a branched new.

**Branched:**

1. After the close PR has merged — **enforced**, not just advised: `TASKS iteration-new <branch> [--parent p] [--name n] [--iteration N] [--iteration-started D]` refuses while the current integration branch is not yet contained in the parent, since the new board starts from the parent and would otherwise be missing the last iteration's archive and log.md close section. Land it first; there is no override. This starts a fresh board on the new branch **and commits a pointer to the board.yml of both the parent and the old iteration branch** so a checkout left on either auto-resolves to the new iteration (with a warning to switch). Those pointer commits push to the parent and the old branch — on a push-protected one it will warn, and checkouts on it then need a one-time `TASKS init --integration <branch>`. The new index defaults to one more than the max of the live index and every archived index; `--iteration N` sets it explicitly and is refused if that number already has an archive.
2. Remind the user: `git checkout <branch>`.
3. The script reseeds what carries over — do not walk it. Everything that carries over is renumbered compactly, 1..N in old-id order, with a `carried from <n>/T<id>` note. Tasks closed with `--carry` keep status, assignee, branch and PR (their worktrees are found by branch; PR titles keep the old `[n/T<id>]` prefix), and their open PRs based on the old integration branch are retargeted to the new one (a failed retarget warns with the `gh pr edit` to run). Later and shelved tasks come back still later or shelved, and recurring tasks armed (a shelved recurring one stays shelved). Deps and `Dev-batch:` lines among them are remapped; deps and batch members on tasks that did not come back (done, not-planned) are dropped. Anything left behind by `--force` is re-added by hand from `.tasks/archive/<n>-<slug>/NNN.md`.
